## Overview

This project is a **learning-friendly DevOps demo** that covers:

- A simple Java HTTP server (no frameworks, plain JDK)
- Maven as the build tool
- An Azure DevOps pipeline (`azure-pipelines.yml`) with separate **Build** and **Deploy** stages
- Automated deployment to a **local Windows agent pool** (`Local-Windows-Pool`)

When the application is running, visiting `http://localhost:8080` returns a plain-text greeting confirming the environment and version.

## Getting Started

### Clone the Repository

```bash
git clone <repository-url>
cd java-devops-demo
```

### Build Locally

Use Maven to compile the code and package it into a runnable JAR:

```bash
mvn clean package
```

This produces `target/java-devops-demo-1.0.0.jar`.

### Run Locally

```bash
java -jar target/java-devops-demo-1.0.0.jar
```

Expected console output:
```
Java application started on port 8080
```

Open your browser or use `curl` to verify:

```bash
curl http://localhost:8080
```

Expected response:
```
Hello from Java!

Application: DevOps Demo
Environment: Local Windows
Deployment: Azure DevOps
Version : 2
```

| Item | Detail |
|------|--------|

| Main class | `com.example.App` |

| Port | `8080` |
| Endpoint | `/` (handles all requests) |
| Java version | 21 (uses text blocks) |

The server is intentionally dependency-free — no Spring, no Quarkus, no external libraries — so the focus stays on the DevOps pipeline rather than the application framework.

## CI/CD Pipeline

The pipeline is defined in [`azure-pipelines.yml`](azure-pipelines.yml) and is triggered automatically on every push to the `main` branch.

```
Push to main
     │
     ▼
┌─────────────┐       ┌──────────────┐
│  Build Stage│──────▶│  Deploy Stage│
│  (Maven)    │       │  (PowerShell)│
└─────────────┘       └──────────────┘
```

The pipeline runs on the **`Local-Windows-Pool`** agent — a self-hosted Azure DevOps agent running on a Windows machine.

### CI Stage – Build

1. **Maven build** — runs `mvn clean package` using JDK 21 (x64).
2. **Verify JAR** — lists the `target/` directory to confirm the JAR was produced.
3. **Publish artifact** — uploads `java-devops-demo-1.0.0.jar` as the pipeline artifact `java-app` for the deploy stage to consume.

### CD Stage – Deploy

Depends on the **Build** stage completing successfully.

1. **Download artifact** — retrieves the `java-app` artifact from the build stage.
2. **Deploy via PowerShell**:
   - Creates `C:\apps\java-devops-demo\` if it does not exist.
   - Stops any running instance (by matching the JAR name in the process command line, and as a fallback by releasing port `8080`).
   - Waits 5 seconds for the OS to free the port.
   - Copies the new JAR into the deploy directory.
   - Starts the application as a hidden background process, redirecting stdout → `app.log` and stderr → `app-error.log`.
   - Waits 5 seconds, then verifies the process is still alive — fails the pipeline if it exited immediately.

## How Deployment Works

```
Azure DevOps Agent (Local Windows)
│
├── Downloads java-devops-demo-1.0.0.jar
├── Stops the old java process (if running)
├── Copies JAR  →  C:\apps\java-devops-demo\java-devops-demo.jar
├── Starts:  java -jar C:\apps\java-devops-demo\java-devops-demo.jar
├── Logs  →  C:\apps\java-devops-demo\app.log
└── Errors →  C:\apps\java-devops-demo\app-error.log
```

After a successful deploy the application is accessible at `http://localhost:8080` on the Windows host running the agent.

## Troubleshooting

| Problem | Likely Cause | Fix |
|---------|-------------|-----|
| `Port 8080 already in use` | Previous instance still running | Run `netstat -ano \| findstr :8080` and stop the listed PID |
| Build fails with Java version error | Wrong JDK active | Set `JAVA_HOME` to JDK 21 and ensure it is on `PATH` |
| `mvn` not found | Maven not installed or not on `PATH` | Install Maven and add its `bin/` folder to `PATH` |
| Pipeline fails at Deploy stage | Build stage artifact missing | Check the Build stage logs for Maven errors |
| Application exits immediately after deploy | Runtime error | Check `C:\apps\java-devops-demo\app-error.log` |
| Azure DevOps agent offline | Agent service not running | Start the agent service on the Windows host |
